# Распознавание плана квартиры из изображения

Прототип для автоматического распознавания стен и комнат на архитектурных планах квартир.

## О проекте

Система принимает 4 изображения планов квартир (JPG) и возвращает JSON с базовой структурой:
- Метаинформация об исходных файлах
- Распознанные стены (линии или полилинии)
- Контуры помещений (полигоны)

## Этапы пайплайна

### 1. Предобработка изображений
- Конвертация в grayscale
- Автоматическая инверсия (если стены темные на светлом фоне)
- Бинаризация для четкого разделения стен и фона
- Морфологические операции для закрытия разрывов в стенах

### 2. Детекция стен
- Поиск внешних контуров с помощью `cv2.findContours()`
- Аппроксимация контуров полигонами с помощью `cv2.approxPolyDP()`
- Разбиение многоугольников на сегменты (отдельные стены)
- Фильтрация по длине (игнорирование коротких сегментов)
- Удаление дубликатов и похожих стен

### 3. Детекция комнат
- Поиск замкнутых контуров помещений
- Аппроксимация многоугольниками комнат
- Фильтрация по площади (игнорирование слишком маленьких/больших областей)
- Проверка минимального количества углов (не менее 3)

### 4. Формирование результата
- Структурирование данных в формат JSON
- Ручное форматирование для точного соответствия требованиям
- Сохранение результатов в файл `output/result.json`

## Используемые инструменты и модели

### **OpenCV (классический Computer Vision)**
- **`cv2.findContours()`** - для поиска границ стен и комнат
- **`cv2.approxPolyDP()`** - для упрощения контуров до многоугольников
- **`cv2.threshold()`** - для бинаризации изображений
- **Морфологические операции** - для очистки и соединения линий
- **`cv2.HoughLinesP()`** - для детекции прямых линий

### **NumPy**
- Обработка матриц и математических операций
- Работа с координатами и геометрическими вычислениями

### **Python Standard Library**
- **`json`** - для формирования выходного формата
- **`os`** - для работы с файловой системой
- **`math`** - для геометрических расчетов

## Почему выбран этот стек/модели

### **Обоснование выбора классического CV вместо нейросетей:**

1. **Адекватность для класса данных:**
   - Архитектурные планы состоят из четких геометрических примитивов
   - Высокий контраст между стенами и фоном
   - Прямые линии и правильные многоугольники идеально детектируются классическими методами

2. **Практические преимущества для прототипа:**
   - **Нет необходимости в обучающих данных** - не требуется размеченный датасет
   - **Быстрое прототипирование** - алгоритмы работают "из коробки"
   - **Интерпретируемость** - каждый шаг пайплайна понятен и отлаживаем
   - **Низкие требования к железу** - работает на CPU, не требует GPU

3. **Сравнительная простота:**
   - Меньше зависимостей по сравнению с ML-фреймворками
   - Проще развертывание и поддержка
   - Прозрачная логика работы

### **Альтернативы, которые рассматривались:**

- **Нейросети (YOLO, UNet, DeepLab, SAM)** - отвергнуты из-за сложности и необходимости в данных
- **Гибридный подход** - оставлен для будущих улучшений
- **Специализированные библиотеки** - не найдено готовых решений для архитектурных планов

## Слабые места текущей реализации

### **1. Зависимость от качества входных данных:**
- Требует высококонтрастных, четких изображений
- Плохо работает с размытыми или сжатыми планами
- Чувствительность к толщине линий стен

### **2. Ограничения алгоритмов:**
- Только прямые стены (проблемы с криволинейными архитектурными формами)
- Не реализовано распознавание окон, дверей, проемов
- Не обрабатывает наложенный текст и размеры

### **3. Параметрическая настройка:**
- Пороговые значения подобраны эмпирически
- Требует ручной настройки для разных стилей планов
- Жесткие ограничения (например, минимум 4 точки для стены)

### **4. Топологические проблемы:**
- Нет проверки корректности плана (пересекающиеся стены, незамкнутые помещения)
- Не различает несущие стены и перегородки
- Проблемы с совмещением стен из разных контуров

### **5. Формат вывода:**
- Координаты только в пикселях, без привязки к реальным размерам
- Нет информации о толщине стен

## Что улучшить в следующей итерации

### **Высокий приоритет:**

1. **Детекция окон и дверей:**
   - Использование шаблонного сопоставления для стандартных элементов
   - Добавление в выходной JSON с типами и размерами

2. **OCR для размеров:**
   - Интеграция Tesseract OCR для чтения текстовых меток
   - Парсинг размеров и их привязка к соответствующим стенам/комнатам

3. **Коррекция перспективы:**
   - Автоматическое выравнивание наклонных фотографий планов
   - Компенсация искажений от фотосъемки

### **Средний приоритет:**

4. **Улучшенная детекция стен:**
   - Комбинирование Hough Transform с контурным анализом
   - Поддержка криволинейных стен

5. **Валидация топологии:**
   - Проверка корректности плана (все комнаты замкнуты, нет пересечений)
   - Определение несущих конструкций

6. **Поддержка разных форматов:**
   - Обработка векторных форматов (DXF, SVG)
   - Работа с PDF-файлами, содержащими планы


### **Технологический стек для улучшений:**

1. **Segment Anything Model (SAM)** - для точной сегментации помещений
2. **YOLO/Detectron2** - для детекции мебели и оборудования
3. **Pytesseract** - для OCR функционала
4. **Scikit-image** - для дополнительных методов обработки изображений
5. **Гибридный подход** - классический CV для предобработки + нейросети для сложных задач
